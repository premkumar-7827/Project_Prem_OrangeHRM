# OrangeHRM QA Automation

Playwright + TypeScript end-to-end automation for an OrangeHRM employee lifecycle, with authenticated API checks, HTML/JUnit reporting, GitHub Actions, and an optional k6 API performance smoke test.

## Prerequisites

- Node.js 22 and npm
- Git
- Optional: k6 for performance tests
- An OrangeHRM test environment with an administrator account; configure a separate ESS account to enable role-differential assertions

The default URL and credentials target OrangeHRM's public demo. Prefer a dedicated, disposable test tenant: the lifecycle test creates, edits, and deletes a real employee record.

## Setup and execution

1. Install packages with `npm ci` (use `npm install` once if creating the lockfile locally).
2. Copy `.env.example` to `.env` and set `BASE_URL`, `HRM_USERNAME`, and `HRM_PASSWORD`. Add `ESS_USERNAME` and `ESS_PASSWORD` for the ESS-specific test. Do not commit `.env` or credentials.
3. Install the browser with `npx playwright install chromium`.
4. Run all checks with `npm run typecheck` and `npm test`.
5. Run only smoke tests with `npm run test:smoke`; run the employee lifecycle with `npm run test:regression`.
6. Open the HTML report with `npm run report`.

PowerShell example for one-off environment configuration:

```powershell
$env:BASE_URL = 'https://your-orangehrm-test-host'
$env:HRM_USERNAME = 'your-test-admin'
$env:HRM_PASSWORD = 'your-test-password'
npm test
```

## Architecture and design decisions

- `src/pages/` uses Page Objects to isolate UI selectors and user actions.
- `src/api/` contains a small authenticated API client used to verify persisted employee state independently of the UI.
- `src/config/env.ts` centralizes environment settings; secrets are read from environment variables and `.env` is ignored by Git.
- Employee IDs are generated uniquely per run. The lifecycle test performs best-effort API cleanup if an assertion fails before UI deletion.
- Tests use Playwright locator auto-waiting and web-first assertions rather than fixed delays. CI retries are enabled twice to expose transient failures while keeping retries out of local runs by default.
- Tags are embedded in test titles (`@smoke`, `@regression`, `@e2e`, `@auth`) and selected with `--grep`.
- Admin and anonymous access checks run by default. ESS-vs-admin checks are skipped with an explicit reason unless a dedicated ESS account is configured; this avoids conflating unauthenticated access with role-based authorization.

## Reliability and flaky-test approach

Flakiness is tracked from retry outcomes, traces, screenshots, videos, and repeated CI history. A test that passes only on retry remains a signal to investigate, not a clean pass. Diagnose whether the cause is a race, unstable test data, environment availability, or a product defect; do not hide failures by increasing retries indefinitely.

Mitigations include semantic locators, bounded smart waits, unique test records, deterministic cleanup, low parallelism against shared environments, and trace/video/screenshot evidence on failure. For CI, `retries: 2` helps capture intermittent failures while the HTML/JUnit reports retain the original attempt details.

## CI/CD and artifacts

`.github/workflows/qa.yml` runs on pushes, pull requests, and manual dispatch. It installs dependencies and Chromium, type-checks, runs tests, and uploads the HTML report plus `test-results/` (JUnit, traces, screenshots, and retained failure videos) for 14 days. Configure `BASE_URL` as a repository variable and credentials as repository secrets. Optional ESS credentials enable the extra authorization test.

Reports are generated by the run and uploaded as workflow artifacts; they are intentionally not committed as stale build output. Download the artifact from the GitHub Actions run to review results.

## Optional k6 API performance test

Install k6, then run `npm run perf:smoke` with the same `BASE_URL`, `HRM_USERNAME`, and `HRM_PASSWORD` environment variables. The script measures login and employee-creation API latency, applies p95 thresholds, checks outcomes, and deletes created employee data. It writes `performance/summary.json` and `performance/summary.html`.

The GitHub Actions workflow runs k6 only through manual dispatch with `run_k6` enabled. Keep the default load low and run against an environment you own or are authorized to test; do not load-test the shared public demo. Thresholds are starter objectives and should be tuned to the target environment's SLOs.

## Scope notes

The lifecycle flow covers login, administrator access, employee create/update/delete through the UI, and API-level persistence checks. A real ESS role check requires a provisioned ESS user in the target tenant. API routes and response shapes can vary by OrangeHRM version; validate them against the version under test before using this against a different deployment.
